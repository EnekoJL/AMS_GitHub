# AMS Firmware – Project Architecture

## Project Overview
Firmware for an electric competition motorcycle by **AMS (Araba MotorSport)**.
- **Target hardware**: STM32F469 Discovery Board (Cortex-M4, 180 MHz)
- **Current runtime**: Bare-metal (no RTOS). The main loop uses `HAL_GetTick()` for cooperative, non-blocking scheduling.
- **Near-term goal**: Migrate to FreeRTOS tasks. The DataBroker layer is already prepared for mutex-based protection.

---

## Layered Architecture (SOLID Principles)

The project follows a strict layered architecture with Dependency Inversion and Single Responsibility.
Dependencies flow only **downwards**: Application → Middleware → Drivers_Custom → HAL.

```
┌─────────────────────────────────────────────┐
│              APPLICATION (main.c)            │  <- Init + superloop / future task spawner
├─────────────────────────────────────────────┤
│           ALGORITHMS (Domain Logic)          │  <- Pure C, no HAL, no RTOS
├─────────────────────────────────────────────┤
│  MIDDLEWARE (Pseudo-Tasks + DataBroker)      │  <- Coordinates data between layers
├─────────────────────────────────────────────┤
│         DRIVERS_CUSTOM (HAL Wrappers)        │  <- Thin wrappers over STM32 HAL
├─────────────────────────────────────────────┤
│              STM32 HAL (ST generated)        │
└─────────────────────────────────────────────┘
```

## Layer Details

### 1. Application Layer — `Core/Src/main.c`
- Generated by STM32CubeMX. Initializes all peripherals via `MX_*_Init()` functions.
- **Active peripherals**: ADC1, ADC2, DMA2 (two streams), TIM2, TIM3, USART3, SDIO, CAN2, GPIO, FatFS.
- **Clock**: HSE 8 MHz → PLL → 180 MHz SYSCLK (Over-Drive enabled).
- **Main loop**: Non-blocking pattern using `HAL_GetTick()` delta checks.
- Custom init calls to be placed in `USER CODE BEGIN 2` section.

### 2. Algorithms Layer — `Core/Src/Algorithms/` · `Core/Inc/Algorithms/`
Pure domain logic. **No HAL, no FreeRTOS includes allowed.**

| File | Responsibility |
|---|---|
| `AMS_sensors.c/.h` | Converts raw filtered ADC counts → millivolts → physical units (battery voltage mV, suspension travel dmm). Uses voltage divider ratios and potentiometer range constants from `AMS_DataTypes.h`. |

**Functions:**
- `Algorithms_Sensors_ProcessVoltages()` – raw ADC → mV (rule of three, 12-bit range).
- `Algorithms_Sensors_CalculateVehicleData()` – mV → physical quantities (12V battery, suspension 1 @ 150mm range, suspension 2 @ 50mm range).

### 3. Middleware Layer — `Core/Src/Middleware/` · `Core/Inc/Middleware/`

#### DataBroker — `DataBroker.c/.h` *(Central data hub)*
- Holds **all shared state** as `static` private variables. No global variables anywhere else.
- Exposes typed Getters/Setters using `memcpy` for safe copy-by-value semantics.
- **FreeRTOS mutex stubs** are commented in-place as `// [FUTURO FreeRTOS]`, ready to be activated.
- Managed state:
  - `AMS_ADC_Data_t s_adc_data` – filtered raw ADC counts + computed millivolts.
  - `Vehicle_Data_t s_vehiculo_state` – physical vehicle measurements.
  - `AMS_LED_Mode_t s_led_mode` – current LED display mode.
  - `AMS_Persistent_Config_t s_persistent_config` – loaded from Flash on boot.

#### Persistence Manager — `AMS_persistence_manager.c/.h`
- Manages **wear-levelled circular logging** in internal Flash Bank 2 (Sectors 22 & 23, Ping-Pong scheme).
- `vd_Persist_Init()`: scans Flash for the last valid `AMS_Flash_Record_t` (magic + CRC check). Loads config into DataBroker, or defaults if nothing found.
- `b_Persist_SaveConfig()`: writes next free slot; erases the alternate sector and switches to it when the current sector is full.
- Interacts with: `AMS_flash_driver` (raw HAL) and `DataBroker` (data source/sink).

#### Logger Task (Pseudo-Task) — `logger_task.c/.h`
- `vd_Logger_Init()`: mounts SD card, finds next available filename (`gekko_000.csv` → `gekko_999.csv`), opens file, writes CSV header.
- `vd_Logger_Process()`: reads `Vehicle_Data_t` from DataBroker, formats as CSV line (`TICK_MS, BAT_12V_MV, SUSP1_DMM, SUSP2_DMM`), writes + syncs to SD.
- **Future RTOS task**: call `vd_Logger_Process()` in its own infinite loop at a fixed rate.

#### LED Manager Task (Pseudo-Task) — `led_manager_task.c/.h`
- State machine driven by `AMS_LED_Mode_t` from DataBroker.
- Non-blocking blink using `HAL_GetTick()` delta (500 ms period).
- Supported modes: ALL_OFF, ALL_ON, ALL_BLINK, GREEN/RED/BLUE/ORANGE ON and BLINK.
- Calls `AMS_led_driver` for actual GPIO toggling.
- **Future RTOS task**: call `vd_LED_Manager_Process()` in its own task at ~100 ms.

### 4. Drivers_Custom Layer — `Core/Src/Drivers_Custom/` · `Core/Inc/Drivers_Custom/`
Thin HAL wrappers. Only hardware interaction, no business logic.

| Driver | Responsibility |
|---|---|
| `AMS_adc_driver.c/.h` | Starts ADC1 + ADC2 in DMA mode (triggered by TIM2 and TIM3). Implements `HAL_ADC_ConvCpltCallback` for 10-sample averaging (moving sum), then writes filtered values to DataBroker. |
| `AMS_led_driver.c/.h` | Direct GPIO control for the 4 on-board LEDs (Green=LED1, Orange=LED2, Red=LED3, Blue=LED4) on the Discovery board. |
| `AMS_flash_driver.c/.h` | Raw Flash read/write/erase using STM32 HAL Flash API. Targets Bank 2, Sectors 22–23 (each 128 KB). Validates addresses, manages FLASH_Unlock/Lock internally. |
| `AMS_SD_driver.c/.h` | FatFS wrapper: mount, find next filename, open/write/sync/close. Uses `f_sync` after each write to prevent data loss on power cut. |

### 5. Data Types — `Core/Inc/AMS_DataTypes.h`
Central type definitions. **No initializations, only struct/enum/constant definitions.**

| Type | Description |
|---|---|
| `AMS_ADC_Data_t` | Raw filtered ADC counts + computed millivolt values (ADC1, ADC2-ch1, ADC2-ch2) |
| `Vehicle_Data_t` | Physical values: `bateria_12v_mV`, `recorrido_susp_1_dmm`, `recorrido_susp_2_dmm` |
| `AMS_LED_Mode_t` | Enum of 11 LED states (OFF, ON, BLINK variants per colour) |
| `AMS_Persistent_Config_t` | `soc_percent_x10` + `cycle_count` (persisted to Flash) |
| `AMS_Flash_Record_t` | `magic (0xAEC01AD0)` + `AMS_Persistent_Config_t` + `crc32` = 12 bytes, packed |

## Data Flow (Current Bare-Metal)

```
TIM2/TIM3 (hardware trigger)
    │
    ▼
ADC DMA HW conversion
    │
    ▼
HAL_ADC_ConvCpltCallback  (ISR context)
    │  10-sample average
    ▼
DataBroker ─── AMS_ADC_Data_t
    │
    ▼ (called from main loop / future Sensors_Task)
Algorithms_Sensors_ProcessVoltages()    → mV
Algorithms_Sensors_CalculateVehicleData() → dmm, mV
    │
    ▼
DataBroker ─── Vehicle_Data_t
    │
    ├───▶ Logger_Task → SD Card (FATFS) → gekko_NNN.csv
    └───▶ LED_Manager_Task → LED Driver → GPIO
```

## Code Rules

- **Zero dynamic memory**: no `malloc`, `calloc`, `free`. All buffers are `static`.
- **Explicit types**: `uint32_t`, `uint16_t`, `int16_t`, `float` from `<stdint.h>`.
- **Naming convention**: `AMS_` prefix for all custom files. Function prefixes encode return type: `vd_` (void), `b_` (bool), `u32_` (uint32_t), `e_` (enum).
- **Domain independence**: `Algorithms/` files must not include `stm32f4xx_hal.h` or `FreeRTOS.h`. They receive pointers/values and return results.
- **ISR safety**: The ADC callback runs in interrupt context. DataBroker calls are kept short (memcpy only). No blocking in ISRs.

## FreeRTOS Migration Plan (Next Step)

The codebase is architecturally ready. The following tasks are the immediate next step:

| Future RTOS Task | Period | What it runs |
|---|---|---|
| `Sensors_Task` | 10 ms | `Algorithms_Sensors_ProcessVoltages()` + `Algorithms_Sensors_CalculateVehicleData()` → `b_Broker_Update_VehicleState()` |
| `Logger_Task` | 100 ms | `vd_Logger_Process()` |
| `LED_Manager_Task` | 100 ms | `vd_LED_Manager_Process()` |

**Steps to activate FreeRTOS:**
1. Add FreeRTOS via CubeMX (Middleware → FreeRTOS → CMSIS-RTOS v2).
2. Uncomment mutex declarations and `xSemaphoreCreateMutexStatic()` calls in `DataBroker.c`.
3. Uncomment `xSemaphoreTake / xSemaphoreGive` in every Getter/Setter.
4. Create task files (`Task_Sensors.c`, `Task_Logger.c`, `Task_LED.c`) calling the respective `_Process()` functions with `osDelay()`.
5. Move task creation from `main()` `USER CODE BEGIN 2` into a `vd_App_Init()` function.
6. **Remove the bare-metal while loop logic** and call `osKernelStart()`.
